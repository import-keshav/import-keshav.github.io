Selected systems

A selection of systems where architecture, reliability, and measurable outcomes mattered.

01 · Harness

CodePulse: from operational context to reviewed PR

An internal developer agent that understands repositories, connects engineering context, and executes approved changes through a sandboxed CI workflow.

Challenge
Debugging and routine customer fixes required repeated context gathering and on-call involvement.
System
Request → repository analysis → proposed plan → human approval → sandboxed pipeline → tests → pull request. Built with Go, Slack, LSP, Jira, Confluence, Grafana, Harness APIs, PostgreSQL, and MCP tools.
Outcome
Support teams can diagnose and address customer issues from Slack with less on-call dependency.

Go · Slack · MCP · PostgreSQL · Grafana · Harness APIs

02 · CoinSwitch

High-volatility trading & market making system

Pricing, hedging, order routing, and derivatives systems built for low latency and sustained reliability.

Challenge
Serve millions of traders through volatile markets without depending on third-party market makers or brittle payment paths.
System
Four Python market-making services, a Go derivatives engine, and configuration-driven payments across crypto and other asset classes.
Outcome
$30M+ liquidity delivered, ~50,000 orders/minute, sub-200ms p99 on critical paths, and 99.999% trading availability. Figures come from related systems, not a single component.

Python · Go · PostgreSQL · Redis · Kafka · Kubernetes

03 · Blinkit

Product listing & discovery: 10× latency reduction at 20M scale

Modernized Product Listing and Discovery services while traffic and product complexity were increasing.

Challenge
Legacy listing paths were approaching ~1,000ms while consumer traffic scaled toward 20M users.
System
Python 2/Flask → Python 3/FastAPI, async request processing, and monitoring through Grafana and New Relic.
Outcome
Listing latency reduced from approximately 1,000ms to under 100ms at 20M+ consumer scale.

Python · FastAPI · Grafana · New Relic
